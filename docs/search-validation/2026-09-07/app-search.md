# Initial app search — September 7, 2026

Implemented and verified locally; **not deployed**. Read-only live corpus and
existing inference were used from a local debug `hn_app` preview on port 3081.
No schema, data, database grants, inference deployment or production service was
changed. The Python agent still uses its existing repository.

The page uses the existing HN shell with a small “Search stories” label, plain
square input/button/select, cream background, orange header and ordinary page
links. The initial promotional heading and examples were removed following user
feedback. Query, sort and pagination are normal GET navigation. JavaScript only
shows submission progress and resets the button on browser Back.

## Scope and remaining work

The shared Rust service serves HTML and JSON, but the first UI exposes query and
sort only. Domain/date/score filters, filter-only browsing, query batching,
agent payload parity and agent HTTP cutover remain future work. No legacy FTS
selector was added. Newest uses full timestamps; the Python search currently
sorts by day. Do not call this a complete agent-compatible API yet.

Snapshots contain at most 200 IDs, expire after five minutes and are capped at
128 per app process. No lock is held across HTTP or SQL. Page details recheck
live eligibility; deletion-between-pages was not tested by mutating production.
An app restart or eviction requires a fresh search. Multiple app replicas would
need request affinity or shared snapshot storage before relying on these tokens.

The Rust async database driver did not consume `.pgpass` automatically. The local
preview was launched with the existing read-only credential in its environment;
credentials were never printed or saved in the evidence. README corrected.

## Homepage alignment follow-up

Removed search-only story spacing, typography, pager and mobile-gutter overrides;
search now consumes the homepage styles directly. Shared shell reserves scrollbar
space and fills the viewport even on an empty search. Progress is positioned in
the form's existing bottom gap instead of inserting a new row during submission.

Browser comparison of homepage and search results at 1280×900 and 390×844 confirmed
identical shell/header widths, main padding, row gutters, title and metadata font
sizes/line heights, and 8px story-list gap. Desktop title start: 134.515625px on
both; phone title start: 37.515625px on both. Mobile padding is 8px 4px 24px.
Both pages were visually inspected after the change. Build and all 11 tests pass.

## Rank tooltip experiment

Search result numbers now have native browser `title` tooltips containing vector
rank, BM25 rank and six-decimal RRF score. Missing branches say “not in candidates.”
Metadata stays with cached rankings and is exposed in JSON as `ranks`, keyed by
story ID. No additional retrieval, cutoff, custom popup or layout change.
Homepage numbers remain unchanged. Native hover is the initial desktop experiment;
no separate touch interaction was added.

Build and all 11 tests passed, including assertions for branch ranks and weighted
score. Browser DOM verification on the user's yen query confirmed first result
vector #1 / BM25 #1 / 0.018443 and second result #3 / #6 / 0.017767. The preview
was restarted and the same query reopened without its expired snapshot token.

## Inline details experiment (replaces hover tooltips)

A small accessible Details switch now persists `searchhn.details` in localStorage.
When enabled, metadata after the comment link shows `Cosine 0.512 ・RRF 0.018`.
The preference is applied in the document head before results paint. Storage denial
still permits an in-page toggle. Hover titles and help cursors were removed.

Cosine is computed as `1 - cosine distance` for the bounded fused candidate set
(up to 200 IDs), including BM25-only candidates with embeddings. It is retained
with snapshot ranks, so page changes need no new similarity work. Unavailable
similarity (including inference fallback) displays an em dash. Retrieval ordering
and RRF weights are unchanged; this adds one bounded SELECT per hybrid ranking.

Build and all 11 tests passed. Browser checks on “boosted boards bankruptcy”
confirmed details after comments, on/off operation, persistence after reload,
and no remaining rank tooltips. Desktop and 390px phone layouts were inspected;
phone scroll width equals viewport width. Preview left with Details enabled.
